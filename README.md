# Тестовое Neowise. AI-помощник для входящих заявок

Менеджер вводит текст заявки и получает тему и черновик ответа. Результат AI проверяется на сервере, при любом сбое заявка уходит на ручной разбор. Менеджер сам решает, что отправить клиенту.

## Требования

Node.js 20 или новее (проверено на Node 24). Зависимостей и ключей нет.

## Запуск

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт задаётся переменной `PORT`, например `PORT=3100 node server.mjs`.

## Тесты

```sh
node --test
```

Тесты используют встроенный `node:test`. 14 тестов поднимают настоящий HTTP-сервер на свободном порту и ходят в `POST /api/triage`. Логика страницы проверяется отдельно, с управляемыми заглушками `fetch`.

## Поведение

`POST /api/triage`, тело `{"text": "..."}`:

| Ситуация | Ответ |
| --- | --- |
| `text` пустой (в том числе из пробелов), отсутствует, не строка, тело не JSON | HTTP 400 `{"status":"invalid_input"}` |
| Модель ответила корректно | HTTP 200 `{"status":"ready","topic":"delivery\|pricing\|other","draft":"…"}` |
| Таймаут (300 мс), ошибка модели, невалидный JSON, неизвестная тема, пустой черновик | HTTP 200 `{"status":"manual_review","topic":null,"draft":null}` |

Ответ модели проверяется в `parseModelOutput` (`server.mjs`): это JSON-объект, `topic` из `delivery`, `pricing`, `other`, `draft` не пустой после `trim()`. Ожидание модели ограничено 300 мс: модель получает `AbortSignal`, а `Promise.race` гарантирует ответ, даже если она сигнал игнорирует.

## Страница

- При успехе показываются тема и черновик. Черновик можно править.
- При запуске новой обработки старая тема и старый черновик очищаются сразу.
- Если два запроса завершаются в обратном порядке, ответ устаревшего запроса игнорируется (счётчик запросов и `AbortController`).
- При `manual_review`, сетевой ошибке, ответе не 200 или некорректном ответе показывается сообщение о ручной обработке. Текст заявки остаётся в поле ввода, черновик пустой, и менеджер пишет ответ сам. Пустой результат никогда не показывается как успешный.
- Логика страницы лежит в `triage-client.mjs` и не зависит от DOM, поэтому тестируется без браузера.

## Ручная обработка

Если пришло сообщение «AI не смог подготовить надёжный ответ» или «Не удалось связаться с сервером»:
1. Текст заявки остаётся в поле, его не нужно вводить заново.
2. Откройте поле «Черновик ответа» и напишите ответ вручную.
3. Для повторной попытки нажмите «Разобрать заявку» ещё раз.

## Проверка сбоев имитатора

`mock-ai.mjs` не менялся. Добавьте метку в текст заявки:

| Метка | Что имитирует |
| --- | --- |
| `[timeout]` | ответ через 1200 мс (API ждёт 300 мс) |
| `[error]` | ошибка провайдера |
| `[bad-json]` | невалидный JSON |
| `[bad-topic]` | неизвестная тема `refund` |
| `[empty-draft]` | черновик из пробелов |

Во всех случаях результат `manual_review`. Из командной строки:

```sh
node server.mjs &
curl -s -X POST http://127.0.0.1:3000/api/triage -d '{"text":"Вопрос по доставке [error]"}'
```
